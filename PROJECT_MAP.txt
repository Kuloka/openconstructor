==============================
Зачем этот файл: чтобы ИИ-помощник (и люди) не перечитывали весь код в каждой сессии.
Читать его ПЕРВЫМ, потом открывать только нужные места. Обновлять, когда меняется структура.
Последнее обновление: 2026-11-12

КАК УСТРОЕНО В ДВУХ СЛОВАХ
--------------------------
Браузерный редактор (Vite, ванильный JS + немного React) + Cloudflare Worker (worker.js) + Supabase.
Страница = список элементов (items) на холсте. Элемент = { id, name, code (HTML+CSS), x, y,
  full?: секция на всю ширину, scene?: 3D-сцена, app?: мини-приложение со скриптом, locked? }.
Каждый элемент рисуется в своём <iframe srcdoc>. Обычные элементы: sandbox="allow-same-origin",
  скрипты запрещены CSP. Приложения (app): sandbox="allow-scripts", без same-origin, без сети.
Проект хранится в localStorage ('form-canvas-v3' = items, 'oc-page' = page, 'oc-name').
Облако (projects.js) — зеркало для вошедших. Публикация (publish.js) кладёт готовый HTML в Supabase,
  worker.js отдаёт его на /p/<slug> и на своих доменах.

КОМАНДЫ
-------
npm run dev        — редактор на 127.0.0.1:5173 (/api проксируется на живой воркер, vite.config.js)
npm test           — юнит-тесты (tests/unit/*.test.js), быстрые
npm run test:e2e   — браузерные тесты (headless Chrome, ИИ подделан). ONLY=apps — только часть.
npm run build      — сборка в dist/
npm run deploy     — тесты + сборка + wrangler deploy (основной сайт)
npm run deploy:domains — тот же worker.js для своих доменов пользователей

studio.js (~2000 строк) — ядро редактора. Ориентиры внутри (искать по тексту):
  "── State"            items, undo (checkpoint/pushHistory), persist() → событие oc:changed
  "function nodeDoc"    документ iframe для элемента (app → apps.js appDoc)
  "function render"     синхронизация items → DOM-узлы .node
  "addEventListener('message'"  размеры и ошибки от iframe-приложений
  "function add("       добавить элемент (opts: full, scene, app, pos)
  "function buildHTML"  итоговый HTML страницы (экспорт/публикация); hasApps() → withAppHead
  "function openDevicePreview"  просмотр телефон/планшет/компьютер
  "function setPlaying" ▶ play: iframe получают мышь

  dev-сервер добавляет ?t=… и получится вторая копия редактора.

  превью» = data-tab code|split|preview), панель слева (activity bar), проводник (файлы приложения index.html/style.css/
  app.js и список всех приложений проекта), редактор кода с вкладками и подсветкой, справа от него живой просмотр
  (по умолчанию на всю ширину, есть 390/820/1280, поле ширины, ручки), внизу панель «Проблемы / Консоль» (ошибки и
  console.log приложения — APP_LOG только в этом просмотре), справа чат редактора (#chatPanel переносится внутрь и
  возвращается при закрытии), снизу строка состояния (ошибки, авто-починка, строки по языкам, Стр/Стлб).

  Запросы к ИИ здесь меняют только приложение в фокусе: studio.setCodeFocus(id) → runAI берёт его как target

КАЧЕСТВО ПРИЛОЖЕНИЙ ОТ ИИ (apps.js + runAI)
------------------------------------------
APP_RULES — инструкция: каркас (state + render, события через data-act), правила кода, правила дизайна, формат.
appReference(text) — к новому запросу прикладывается ближайший готовый пример как образец.
В режиме приложений до 3 попыток: пустой ответ и оборванный <script> повторяются (getResult в runAI).
Ошибка скрипта в приложении → метка на холсте + сообщение в чате с кнопкой «исправить» (offerFix в studio.js).
APP_ERR (apps.js) сообщает текст ошибки + номер строки, а также «тихие» баги: NaN / undefined / [object Object] на экране.
В экране Code (code.js) ошибки из просмотра идут ИИ сразу (авто-починка, кнопка «auto-fix», не больше 2 попыток подряд;
  попытки возвращаются, если новая версия 4 с без ошибок). Починка идёт с sameTurn: тот же X-OC-Turn → сервер не списывает
  ещё одну бесплатную генерацию (до 4 вызовов на ход). Пока Code открыт, offerFix на холсте молчит.
  studio.busy() — идёт ли запрос к ИИ; событие oc:ai-idle — запрос закончился (успех или ошибка).
Слушатель ошибок стоит в <head> документа приложения (APP_ERR), иначе ошибки при запуске не ловятся.
eval разрешён ('unsafe-eval'): окно изолировано и без сети, а калькуляторы от ИИ часто им считают.

ПРАВИЛА БЕЗОПАСНОСТИ (не ломать)
--------------------------------
- Пользовательский HTML живёт на нашем домене: только sandbox без allow-same-origin.
- Опубликованные страницы: script-src 'none'; с меткой oc-app — скрипты, но connect-src 'none'.
- Данные из облака/ремикса недоверенные: cleanItems() в studio.js.
- Заголовки безопасности статики (редактор, главная, SEO) — public/_headers (HSTS, CSP, X-Frame-Options…).
  CSP редактора НЕ может запретить inline/eval: фреймы srcdoc (блоки, мини-приложения) наследуют её.
  Ответы воркера на основном домене получают HSTS + nosniff (worker.js, SECURITY/secure()).
  Свои домены пользователей — без HSTS. Контакт для уязвимостей: public/.well-known/security.txt (Expires 2027-11-12).

ПЕРЕВОДЫ
--------
Любой новый текст интерфейса → добавить ключ в locales/ru.js, de.js, es.js, tr.js.

КОНСОЛЬНАЯ ВЕРСИЯ (cli/)
-----------------------
cli/bin.mjs — npm-пакет "openconstructor" (npx openconstructor), без зависимостей, Node 18+.
  cli/ui.mjs — внешний вид: пиксельный куб-лого (LOGO, рисуется полублоками ▀▄, собирается анимацией при старте),
  карточки результата и ошибки в рамках, пиксельная анимация «стройки» во время ответа ИИ. OC_NO_ANIM=1 — без анимаций.
  Чат в терминале → приложение в папке: index.html (разметка между <!-- openconstructor:app --> метками), style.css, app.js.
  Локальный сервер 127.0.0.1:4321+ отдаёт папку и вставляет в HTML REPORTER (только в ответ, не в файл):
  live reload (SSE /__oc/live), ошибки и console.* → POST /__oc/log → терминал → авто-починка (2 попытки).
  ИИ: бесплатный /api/ai на openconstructor.pw (X-OC-Turn) или свой ключ из env (GROQ/GEMINI/OPENROUTER/…; OC_MODEL).
  История версий в .openconstructor/history, /undo. Тест: tests/unit/cli.test.js (поддельный ИИ).
  Публикация в npm делается вручную: cd cli && npm publish.
promo/ — материалы для соцсетей (roblox-export.gif: шаблон → холст → экспорт в Luau; html-export.gif: запрос в чат → ИИ собирает лендинг кофейни → Export → HTML page → файл открыт в браузере → карточка openconstructor.pw, 960×600, 15 с; html-export-result.html — тот самый выгруженный файл).

ПЛАН «APPS» (мини-приложения)
-----------------------------
Этап 1 (сделан 2026-11-10): режим ⚡ app, запуск в изолированном окне, публикация со скриптами,
  раздел на стартовом экране с 4 живыми примерами, экран Code (чат + регулируемый просмотр), e2e-тесты "apps:".
Этап 2: экспорт в папку на компьютере (File System Access API в Chrome/Edge, иначе .zip);
  экспорт в React и т.п. сейчас вырезает скрипты — для приложений нужен свой путь.
Этап 3: хранение данных приложений (ответы, заявки) — нужен SQL в Supabase.
