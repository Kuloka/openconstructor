КАК УСТРОЕНО В ДВУХ СЛОВАХ
--------------------------
Браузерный редактор (Vite, ванильный JS + немного React) + Cloudflare Worker (worker.js) + Supabase.
Страница = список элементов (items) на холсте. Элемент = { id, name, code (HTML+CSS), x, y,
  full?: секция на всю ширину, scene?: 3D-сцена, app?: мини-приложение со скриптом, locked? }.
Каждый элемент рисуется в своём <iframe srcdoc>. Обычные элементы: sandbox="allow-same-origin",
  скрипты запрещены CSP. Приложения (app): sandbox="allow-scripts", без same-origin, без сети.
Проект хранится в localStorage ('form-canvas-v3' = items, 'oc-page' = page, 'oc-name').
Облако (projects.js) — зеркало для вошедших. Публикация (publish.js) кладёт готовый HTML в Supabase,
  worker.js отдаёт его на /p/<slug> и на своих доменах.

КОМАНДЫ
-------
npm run dev        — редактор на 127.0.0.1:5173 (/api проксируется на живой воркер, vite.config.js)
npm test           — юнит-тесты (tests/unit/*.test.js), быстрые
npm run test:e2e   — браузерные тесты (headless Chrome, ИИ подделан). ONLY=apps — только часть.
npm run build      — сборка в dist/
npm run deploy     — тесты + сборка + wrangler deploy (основной сайт)
npm run deploy:domains — тот же worker.js для своих доменов пользователей

КАЧЕСТВО ПРИЛОЖЕНИЙ ОТ ИИ (apps.js + runAI)
------------------------------------------
APP_RULES — инструкция: каркас (state + render, события через data-act), правила кода, правила дизайна, формат.
appReference(text) — к новому запросу прикладывается ближайший готовый пример как образец.
В режиме приложений до 3 попыток: пустой ответ и оборванный <script> повторяются (getResult в runAI).
Ошибка скрипта в приложении → метка на холсте + сообщение в чате с кнопкой «исправить» (offerFix в studio.js).
APP_ERR (apps.js) сообщает текст ошибки + номер строки, а также «тихие» баги: NaN / undefined / [object Object] на экране.
В экране Code (code.js) ошибки из просмотра идут ИИ сразу (авто-починка, кнопка «auto-fix», не больше 2 попыток подряд;
  попытки возвращаются, если новая версия 4 с без ошибок). Починка идёт с sameTurn: тот же X-OC-Turn → сервер не списывает
  ещё одну бесплатную генерацию (до 4 вызовов на ход). Пока Code открыт, offerFix на холсте молчит.
  studio.busy() — идёт ли запрос к ИИ; событие oc:ai-idle — запрос закончился (успех или ошибка).
Слушатель ошибок стоит в <head> документа приложения (APP_ERR), иначе ошибки при запуске не ловятся.
eval разрешён ('unsafe-eval'): окно изолировано и без сети, а калькуляторы от ИИ часто им считают.

ПРАВИЛА БЕЗОПАСНОСТИ (не ломать)
--------------------------------
- Пользовательский HTML живёт на нашем домене: только sandbox без allow-same-origin.
- Опубликованные страницы: script-src 'none'; с меткой oc-app — скрипты, но connect-src 'none'.
- Данные из облака/ремикса недоверенные: cleanItems() в studio.js.
- Заголовки безопасности статики (редактор, главная, SEO) — public/_headers (HSTS, CSP, X-Frame-Options…).
  CSP редактора НЕ может запретить inline/eval: фреймы srcdoc (блоки, мини-приложения) наследуют её.
  Ответы воркера на основном домене получают HSTS + nosniff (worker.js, SECURITY/secure()).
  Свои домены пользователей — без HSTS. Контакт для уязвимостей: public/.well-known/security.txt (Expires 2027-11-12).

РОЙ АГЕНТОВ (studio.js buildSwarm, 2026-11-13)
---------------------------------------------
Новая страница (пустой холст или явное «новый/new/с нуля», SWARM_RE + SWARM_NEW): сначала «архитектор» — один вызов,
JSON { name, reply, css (общая дизайн-система на .pg), sections:[{kind, brief}] } (5–7 секций), затем по ОДНОМУ
параллельному вызову на секцию (SECTION MODE: <style> с селекторами .sN + один <section class="sN">). Каждый агент
стримит в свой слот черновика (build-stage.js swarm()/part()), у каждого свой курсор. Итог: <style>css</style>
<div class="pg">секции</div> → обычная обработка (фото, model:, контраст, motion). План не разобрался → обычный путь.
Сервер (worker.js) считает до 10 вызовов одного X-OC-Turn за одну генерацию (было 4) — НУЖЕН deploy воркера.
e2e: "swarm". thinking() отдаёт стройку через stop.stage().
Число секций = agentLimit() (настройка «Команда агентов»); свои агенты пользователя (myAgents) встают секциями
перед cta/contact/footer, планировщик их не планирует, каждый может идти на своей модели (свой провайдер и ключ).

Холст: в nodeDoc *{animation-timeline:auto!important} — scroll-анимации показывают конечное состояние.
Агенты роя берут за основу компонент каталога: pickRef(kind) в studio.js (REF_KINDS → похожая полноширинная секция).
Стройка рисует линии стыковки (build-stage.js drawLinks: швы между секциями, нити от курсоров к якорям).
Плавающий чат (layout.js, по умолчанию на десктопе ≥900px): окно ответов поверх холста (тащить за шапку, угол — размер,
двойной клик — сброс; L.fx/fy/fw/fh), поле ввода — плашка .float-composer внизу холста; ⇄ — закрепить сбоку / снова плавающее.
Орбита: у каждого логотипа свои часы — останавливается только тот, на который навели.
Плашка ввода (layout.js + studio.css «Liquid-glass»): одна стеклянная плашка, модель справа у кнопки отправки; шторка .fc-grab сверху
(клик или потянуть вниз) прячет её, остаётся .fc-mini «Ask AI /» (клик или клавиша / возвращает), L.fcHidden.
Окно чата, вытащенное за край холста, прячется в край (L.edge left|right, язычок .edge-tab выдвигает обратно); закрытие анимировано.
